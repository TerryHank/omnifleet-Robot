# 手掌检测 → 完整手部 → NanoTrack → Full 手势：部署验证

2026-11-12。用户明确要求执行该链路，并接受约10%–20%的误判容忍度。本次以实现可用链路收尾，不宣称已测得整体误判率，也不新增动作确认门槛。

## 已实现

1. 使用矫正的1920×1080彩色图，保留人体矩形扩展区域中的真实像素，不使用人体掩膜抠手。
2. 首次捕获或当前关键点丢失时，在人体区域运行MediaPipe Full手掌模型的TensorRT FP32引擎；不再用肤色提示和固定网格窗口定位第一只手。
3. 手掌提案生成旋转ROI；若初始ROI没有有效手部关键点，扩大一次裁剪覆盖指尖。候选按当前Full关键点存在分数选取，避免仅按手掌分数错选放低的另一只手。
4. 按21个关键点重新居中，裁出完整手部，再做Full关键点识别。发现阶段和追踪阶段都执行这次居中修正。
5. 找到有效手部后用独立NanoTrack CUDA FP32实例连续定位，关键点校正位置。有效关键点即使暂时无法分清手势也可更新位置；不会因此续发旧手势。
6. 保留掌面旋正、反投影、局部坐标规范化与同帧0/±20度关键点融合。
7. 数字1/2仍按食指、中指的伸屈判断，取消拇指位置本身排除数字的条件；其余指关节判据与控制状态逻辑不变。OK跟随、跟随中忽略1/2、张掌停止等规则未改。

手掌提案分数下限0.001、每个人最多8个提案，只用于召回候选，不表示动作可信度；关键点存在分数仍为原有0.5，没有降低手势准入阈值或增加确认帧数。手掌引擎与手部Full引擎均预加载，NanoTrack也预热。

## 回放结果

使用两组真实矫正输入及当前算法在122 GPU上运行完整链路，无ROS发布或运动输出。首次手掌回放以逐帧冷启动核对，移动追踪片段按连续输入核对；不得把冷启动样本逐帧数当相机帧率或整体准确率。

- 45帧保持一指并移动/转手：此前已获得位置的旧版为43个1、2空；新链路从冷启动开始得到44个1、1空，没有输出2。
- 原有93帧实拍：原有非空手势输出均保留；新增7个两指、1个一指，以及1个摸头场景的张掌输出。该摸头帧属于已观察到的误判，不宣称精度全面不降。
- 较远约132秒的OK及134/136/138/140秒的1、2、1、2：均输出对应手势。132秒的掌部深度估计约1.378m，源自侧会话的投影分析，不是外部测距真值。
- 16张侧会话抽样中另有148秒一指输出，未取得独立动作真值，不计入准确率结论。
- 模拟当前关键点全部空缺：返回空手势，NanoTrack位置仍保留，没有续发旧动作。

新增多一次完整手部居中识别有计算成本：移动一指片段该次GPU回放中位约78.9ms，对照52.1ms；16张冷启动的中位约255.9ms。它们是该回放进程的处理时间，不是遥控端到端延迟或实机稳定帧率。

Full手掌ONNX与FP32 TensorRT在5个真实裁剪的原始输出对照中，坐标最大绝对差约0.000181、logit最大差约0.000027。该对照不等于全部TFLite算子的数值等价性验收。

证据：chain-summary.json、chain-results.json（完整逐帧结果在122阶段目录）、palm-numeric.json。首两版试验恢复了现有跟踪尺度，并改为每帧完整居中后，才消除了移动一指片段的1→2输出；未采用动作延时确认掩盖错误。
