# WSL 多车协同：跟随领车与各车航点导航

当前只提供两种任务：固定领车跟随、每车独立航点导航。自动推举按最新要求暂不实现。2026-10-17 已移除纵队／横队选择及旧 formation、commission、arm、submit 界面操作。生产机器的 motion_enabled 仍为 false；代码中的实际执行路径在隔离 DDS 域验证，不等于实车行驶验收。

## 广播自动接入（2026-10-18）

连接改由车端身份广播建立，已移除框架和静态 Zenoh 连接文件中的车辆 IP。现有中央名称、顺序与运动许可保持原值；新发现车辆的运动许可默认关闭。详见 [广播接入说明](BROADCAST_DISCOVERY.md)。

## 操作

本机普通 Foxglove 默认连接 ws://127.0.0.1:8767，左侧有“跟随领车”和“各车航点导航”两页。

- 跟随：填写车辆顺序，第一辆为初始领车，其余按跟随 2 号、3 号排序。默认 113、104，距离 1.4 m。建议领车也使用本页自己的航点任务，使其同样受 WSL 独立租约约束；人工／本地控制仍保留优先权。跟随车使用领车实际走过轨迹上的滞后目标；轨迹不足时等待领车先行。
- 固定领车：第一辆保持领车身份。领车下线或不可用时取消跟随目标、确认停稳并停止本次跟随；不推举其他车辆，恢复后也不自动续跑，需操作者重新开始。
- 航点：选择车辆，每行输入 x, y, 朝向角度。坐标属于所选车自己的 map；可以导入该车现有航点或追加当前位置。保存后预检，实际执行按原本车导航接口逐点完成，收到成功结果且停稳后再去下一点。失败停止队列，不反复重发失败目标。
- 两功能可以配合：领车执行自己的航点，其他车跟随。跟随车不能同时启动自己的航点队列。
- 服务重启只恢复已保存的航点，不自动恢复活动任务；跟随顺序和距离是本次跟随会话的设置。地图定位会话改变后，原航点必须检查并重新保存才能执行。

实际执行仍须满足 config/framework.json 的每车 motion_enabled、现场部署验证及车端许可／独立租约。Missions 不直接输出速度，所有目标经 /navigation/execute；本车 local_navigation 仍是唯一安全速度出口。本轮没有启用生产车辆运动许可或发送实际目标。

## 避让

同伴车体经 /navigation/peer_map 进入各车 Nav2 PeerLayer，当前在线车体半径 0.39 m。离线同伴保留最后位置并增加到 0.64 m，不会因为失联立即消失。中央使用各车自己的新鲜地图和当前有效变换预检，并沿用用户当前 1 cm 点模型；未修改车端碰撞检查或已保存导航参数。

交叉路径按先申请先通过，剩余路径预留至取消／停稳或到达确认，走过的部分随定位推进而释放，允许跟随车沿后方轨迹前进。其他车辆等待并重新检查，车端同时用自己的实时障碍和同伴地图重规划。没有假定仅靠同伴地图就能解决所有窄通道或目标互占死锁；无法通过时界面显示受阻／等待，需要调整目标或让出空间。

## 域与地图

WSL 为中央 ROS Domain 42；104、113 分别保留 Domain 104、113，独立进程原生 Zenoh。车内 ROS 和 TF 不增加前缀，中央前缀由 central.assignments 唯一分配。

共享图参考 113。参考车临时离线时，其他车辆的会话匹配变换和自己的实时地图仍可使用；共享参考图标记为缓存。已知任一定位会话改变就撤销旧非参考变换，等待静止自动配准，不把旧变换绑定给新会话。

参数与身份配置在包 config/framework.json。各车航点属于任务数据，保存于 data/missions/routes.json，彼此独立并绑定保存时的定位会话；不覆盖车端原有航点文件。运行状态在 data/connection_status.json、data/map_hub_status.json、data/fleet_alignment.json、data/registration-job.json。

## 代码

- missions.py：固定领车、领车轨迹、分车队列、异步预检、路径预留、取消和会话隔离。
- control_client.py：各车独立域中的许可／租约、导航 Action、准备回执、取消和迟到回调隔离。
- map_hub.py：中央前缀、地图与同伴占用、缓存参考图和离线车体。
- central.py / control_http.py：本机界面命令、状态、ROS 数据汇聚；旧编队 API 不再接收。
- registration.py：保持静止后自动重新配准新地图会话。
